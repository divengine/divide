# 2.31 Variables del sistema

Las variables del sistema las proporciona el motor y se exponen a las plantillas.

|Variable del sistema|Descripción|
|---|---|
|div.now|Resultado de `time()`|
|div.post|`$_POST`|
|div.get|`$_GET`|
|div.server|`$_SERVER`|
|div.session|`$_SESSION`|
|div.version|Versión del motor|
|div.script_name|`$_SERVER['SCRIPT_NAME']`|
|div.ascii|Tabla ASCII (p. ej., `{$div.ascii.64}` da `@`)|

Por defecto solo está habilitado un subconjunto: `div.now`, `div.version`, `div.get` y `div.post`.

Habilita o deshabilita una variable del sistema con `div::enableSystemVar()` y `div::disableSystemVar()`.

## 6.31.1 Variables de configuración del motor

El motor también lee variables de configuración de los items o de las variables de la plantilla. No son variables del sistema, pero afectan al análisis:

- `div.literals`: lista de nombres de variables tratadas como literales (se omite su análisis posterior). Puedes definirla en la plantilla o en PHP. Ejemplo: `{= div.literals: ["text1", "text2"] =}`. Equivalente en PHP: `$tpl->addLiteral(["text1", "text2"]);`
- `div.clear_locations`: indicador booleano que controla si las etiquetas de ubicación se limpian durante los ciclos de análisis. Si es false, las ubicaciones se conservan para seguir componiendo (útil con plantillas preprocesadas). Al final del análisis de nivel superior, las etiquetas de ubicación que queden se limpian.

**Ejemplo**

index.php

```php
<?php

session_start();

include 'div.php';

div::enableSystemVar('div.session');

if (isset($_GET['user'])){
    if ($_GET['user'] == 'peter'){
        $_SESSION['user'] = $_GET['user'];
    }
}

echo new div('index.tpl');
```

index.tpl

```html
?$div.session.user
    ?$div.get.user
        - Welcome {$div.get.user}
    @else@
        - Access denied for user {$div.session.user}
        - Show the login form
    $div.get.user?
@else@
    Show the login form
$div.session.user?
```

Salida

```html
Welcome peter
```
